# Changelog

## Unreleased

- New `barako up`, `status`, `down` and `reset`: a local stack (Postgres, core 5.9.0, Press, Brew and Caddy) from images pinned by digest, started with Docker Compose. `up` writes its files and generated secrets to `~/.barako/stack` (`.env` is mode 0600), waits for the stack, signs in as `admin`, creates the tenant `client`, applies the `site` kit and then a kit (`--kit <name|path>`, default `blog`) and writes an API key (365 days) to `~/.barako/stack/api-key` (mode 0600) for `barako mcp`. A second `up` does not sign in or make a key again, it only checks that the key works. `up` says so when it keeps a key from an earlier run, and when a kit file was edited since the last one. `--latest` uses the newest published images. `down` keeps the data, `reset` deletes it. Neither password nor key is printed. `up` waits until every service has run 10 seconds without a restart (on a running stack only when one started less than 10 seconds ago), and names one that keeps restarting. Needs Docker Compose 2.17 or newer. The site is on `http://client.localhost:8080` and the console on `http://admin.localhost:8080`.
- The stack pins Press 0.19.2. A site opened before `up` creates its tenant no longer keeps a cached 404 home page after the tenant exists.
- The client accepts admin API contract 17 (barakoCMS 6.0.0, which refuses a name, slug or code that ends with a line feed). It still works against 1 to 16.
- `barako schema <type>` and the MCP tool `get_content_type` also return `dataSchema`, a JSON Schema (draft 2020-12) for the data of an entry, built from the type's fields. It describes what core 5.9.0 accepts and does not validate: the API still checks every value. It lists only the fields the caller may read and allows other keys. Through MCP it is left out when the result would be over 256 KB. A test fails when core describes a field type the CLI does not map. The integration suite now uses the 5.9.0 image.
- `barako mcp --allow-writes` adds write tools behind plan and apply (create, update, status change), and `--allow-destructive` adds rollback and erase. A plan returns a one-time token (in memory, 10 minutes). Apply of an update, a status change, a rollback or an erase re-reads the entry first. Apply of a create does not. Default stays read only. Fixes a `__proto__` key being dropped from scrubbed output.
- New `barako mcp`: an MCP server over stdio with four read tools (content types, one content type, entries, one entry). Read only, no network port, no new dependency. Results are wrapped as untrusted data, capped at 256 KB and 100 entries per page.
- Breaking: a credential is no longer sent over plain `http:` to a host that is not loopback. `createClient` throws when `apiKey`, `token`, `refreshToken` or a stored token is set and `baseUrl` is `http:` to anything but `localhost`, `127.x.x.x` or `[::1]`. `auth.login`, `auth.refresh`, `auth.logout` with a refresh token, the automatic refresh and any request that carries an `Authorization` header throw before sending. Use `https:`, or set the new `allowInsecureHttp: true` on a trusted network (a compose service such as `http://api:8080` is not loopback). A client with no credential can still read over http. Login, refresh, logout with a refresh token and the automatic refresh now send with `redirect: "error"`, so a 307 or 308 can never resend the password or refresh token; the call fails with a network error saying the auth endpoint redirected. Every other request still follows redirects. A relative `baseUrl` is not checked. A store that throws when `createClient` reads it (the browser store during server rendering) is skipped there and checked when a request carries its token. Anyone who calls a non-loopback http URL with a credential today must change the URL or opt in.
- The `barako` CLI refuses the same case. Pass `--allow-http` or set `BARAKO_ALLOW_HTTP=1` to opt in.
- `BarakoClient` has a new required member `resources`, so a hand-built object typed as `BarakoClient` stops compiling until it adds one.
- A definition's `update` route takes an optional `merge: "data"`, which tells callers that the row keeps its fields under `data`. The built in `contents` update sets it. A path for `get`, `update` or `delete` must hold `{id}` exactly once.
- A definitions file that holds an unknown key names it only when it is short and plain.
- New `cms.resources`: a table of resources (`names()`, `definition(name)`) and `call(name, verb, { id?, body?, query?, dryRun?, ifMatch?, signal?, timeoutMs? })`, which runs one verb through the client's own transport. New config `resources` adds definitions to the built in table (`contents` without a delete, and `content-types`). A definition is a name and a route per verb (`{ method, path, dryRun? }`, path a template whose only placeholder is `{id}`). A bad definition or a built in name throws from `createClient`. New exports: `BUILTIN_RESOURCES`, `RESOURCE_VERBS`, `checkResourceDefinitions`, `routeLabel`, `verbsOf` and the types `ResourceDefinition`, `ResourceRoute`, `ResourceMethod`, `ResourceVerb`, `ResourceCallOptions` and `ResourcesApi`.
- The `barako` CLI gains `get`, `list`, `create`, `update`, `delete` and `resources` over that table, and `--resources FILE` or `BARAKO_RESOURCES` to add a module's resources from a JSON file.
- Reads (GET and HEAD) now stop after 30 s by default, with a `BarakoError` with `code: "timeout"`. Writes have no default limit. This changes a default: a read that used to wait forever now rejects. Set `timeouts: { readMs: 0 }` to keep the old behaviour. The token refresh uses `readMs`, also `auth.refresh()`. A timeout is at most 2147483647 ms, in config and per call, and a larger value throws.
- New config `timeouts` (`readMs`, `writeMs`), `signal` and `onContractMismatch`. Every method that makes a request takes a trailing `{ signal, timeoutMs }` (not `public.fileUrl` or `auth.isAuthenticated`). A per-call `timeoutMs` that config would reject throws before any request. On `contents.create` and `contents.update` the two fields join the existing options object.
- `BarakoError` has an optional `code` (`timeout`, `aborted`, `network`, `invalid-json`) and `outcomeUnknown`, set when a write timed out or lost its connection. The client never retries after a timeout or a network error.
- A failed token refresh keeps both tokens unless the API answers 400 or 401. Before, any failure signed the user out. A refresh that answers 403, 429 or 5xx rejects with "Token refresh failed." in the message and the refresh's status. A refresh 200 without a non-empty `token` is an `invalid-json` error. The refresh now uses the `baseUrl` without a trailing slash, as other calls do. A call's own `signal` and `timeoutMs` bound how long it waits for the shared refresh, and do not cancel it for other callers. A refresh that finishes after a logout, a login or a tenant switch does not write or clear the tokens. `timeoutMs` counts per attempt, so a call that gets a 401 can wait that long for the refresh and again for the retry.
- `auth.login`, `auth.logout`, `me.switch`, and `contents.create` and `contents.update` with `dryRun` count as reads, so they get the 30 s default, and a timed out dry run no longer says the outcome is unknown.
- A non-2xx response whose body cannot be read is a `BarakoError` with the response's status, not a network error.
- A write that is aborted after it was sent has `outcomeUnknown: true` and says so. An abort before it was sent does not.
- A network error reason is cut to 500 characters on one line, and `scheme://user:pass@` in it becomes `scheme://***@`. `createClient` throws for a `baseUrl` with a user or password.
- `contentTypes.list`, `contents.history` and `me.tenants` stop with an error after 1000 pages. `timeoutMs` applies per page.
- The `barako` CLI reports a client timeout, abort or network failure as a network error, exit 6.
- A 2xx answer with a body that is not JSON rejects with a `BarakoError` (`invalid-json`) instead of a `SyntaxError`. A non-JSON error body is cut to 500 characters in `message` and `body`.
- The client reads `X-Api-Contract-Version` and `X-Delivery-Contract-Version` and warns once per surface when the API is outside the supported range (a delivery header that is present but not a whole number counts as missing, and does not fall back to the admin number) (admin 1 to 17, delivery 1 to 10, exported as `SUPPORTED_CONTRACT`).
- New command `barako-client check-contract <api url> [--strict]` for CI. Exit 0 in range or newer than the client, 1 older than the client or a missing header (and newer with `--strict`), 2 unreachable, a 5xx with no contract header, or bad arguments (a URL with a user or password included). The URL's path is kept and a query or fragment is dropped.
- Known limit: a refresh that times out after the server already rotated the token leaves the client holding the old one. The server's replay rule decides what happens next.
- `me.switch()` sends the tenant as `tenant`, the name barakoCMS reads since 4.6, and still as `club` for older APIs.

## 0.5.0

- `ContentStatus` is now a string enum whose values are names ("Draft", "Published", "Archived", "Scheduled"), to match the API, which sends enums as names. Before, `entry.status === ContentStatus.Published` was always false.
- New string enums `SensitivityLevel` and `FieldMask`. `sensitivity` and `mask` are typed with them instead of `number`.
- Code that passes raw numbers (for example `setStatus(id, 1)`) must use the enum instead.
